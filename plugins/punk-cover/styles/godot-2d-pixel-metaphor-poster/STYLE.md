## 主題理解

- 在內部提取主題的表面含義、深層含義、核心衝突、主要情緒和最適合視覺化的關係，但不展示分析過程。

- 按“抽象概念 → 具體場景 → 遊戲機制 → 視覺隱喻”的順序完成轉譯。場景必須讓觀眾感到這是一種可以被玩家體驗的處境，而不是一組解釋性圖標。

## 遊戲機制隱喻

- 方向衝突：用反向道路、傳送帶、移動平台、錯誤箭頭或消失終點表達努力方向錯誤、越努力越遠或追逐錯誤目標。
- 距離關係：用遠方城堡、山頂、出口、階梯或橋樑表達遙遠目標、時間積累和長期主義。
- 尺度反差：用微小角色面對巨大機器、巨塔、城市、系統或怪物，表達人與 AI、時代或規則的關係。
- 循環困境：用循環道路、無限樓梯、重複房間或閉環地圖表達內耗、重複勞動和無法突破。
- 光暗對比：用黑暗空間中的單一光源、出口、火焰或森林入口表達希望、覺醒和選擇。
- 建造與積累：用城堡、圖書館、基地、升級結構或資源積累表達知識、成長、複利和長期價值。
- 資訊與注意力：用資料洪流、通知怪物、安靜森林或隱藏區域表達 AI 時代、資訊洪流和專注力。
- 這些是關係詞典，不是固定範本。先內部構思多個方向，最終只選擇最容易理解、最有視覺衝擊、最適合單張海報且最有情緒反差的一個隱喻。

## 單一場景與構圖

- 畫面必須只有一個主要角色、一個明確動作、一個核心象徵物、一個目標或阻礙、一個視覺焦點和一塊合理留白。
- 不增加第二主角、第二主要隱喻或複雜支線故事。環境可以豐富，但所有地形、建築、道具和光源都必須服務同一個機制關係。
- 可使用左文字右場景、上文字下場景、中心壓迫、遠近距離、對角線運動或環形循環構圖；依據主題和比例選擇一種，不平均混合。
- 成品應像真實存在的獨立遊戲宣傳海報：具有完整世界觀、環境敘事和關卡空間，但不是遊戲截圖、概念草圖、普通插畫或 UI 介面。

## 比例適配

- `16:9` / `3:2` 橫版：強化左右關係、橫向移動和完整世界景深，讓角色與目標形成清楚距離，標題進入留白區或場景結構。
- `4:5` / `9:16` 豎版：強化上下空間、攀登或墜落路徑，把目標放在遠方或上方，標題位於頂部、中上區域或垂直地形中。
- `1:1` 方形：集中為一箇中心符號或閉環關卡，縮短閱讀路徑並強化縮略圖識別度。
- 自訂比例：重新設計標題位置、角色比例、場景空間、視覺動線和留白。禁止把固定橫版範本直接裁切到其他比例。

## 標題與場景融合

- 使用者輸入的主題原文必須完整、準確地至少出現一次，使用清晰可讀的中文或英文像素字體，並保持海報級排版。
- 文字不能浮貼在場景上。標題可以成為建築、道路、關卡邊界、遠方目標、光源、可破壞地形或環境符號，也可以被機械局部遮擋、產生受控像素故障，或與角色動作發生關係。
- 從主題原文選擇 1–3 個關鍵詞，通過放大、改色、錯位、破碎、發光、陰影或像素化形成第一層衝擊，但不能損害完整原文的可讀性。
- 除主題原文外不增加大量說明文字、隨機英文、日期、版本號、品牌、Logo 或虛構遊戲資訊。

## Godot 2D 像素語言

- 呈現為 Godot 製作的獨立遊戲二維像素藝術：手動逐像素繪製感，16-bit / 32-bit 視覺密度，清晰硬邊像素，統一 Sprite 比例，Tilemap 環境和真實關卡設計邏輯。
- 角色、環境、標題、地形、粒子和陰影必須共享一致的像素網格與解析度邏輯；不能混合不同像素尺度、平滑向量邊緣或高解析度照片元素。
- 使用像素藝術內部的電影級光影、景深分層、霧氣、局部光源和環境敘事，但保持像素邊緣清楚，不使用模糊濾鏡掩蓋細節。
- 不是給普通圖片添加像素濾鏡，不是 3D 繪製後降取樣，也不是模仿現成遊戲的角色、地圖、Logo 或具體美術資產。

## 色彩系統

- 根據主題自動選擇一套有限、統一且有主次面積的像素調色板，不固定顏色。
- 明亮冒險方向可用藍天、草地、陽光和清新綠色；暗黑幻想方向可用深藍、黑、暗紅和火光；科技未來方向可用藍紫、資料光和剋制霓虹；溫暖成長方向可用黃昏橙光、紫色天空和治癒氛圍。
- 色彩必須服務主題和隱喻，不照搬固定遊戲配色，也不要讓所有顏色平均競爭。
- 參考圖中的明亮平台冒險世界、橫向關卡和遠方城堡是一種代表性實作，不是固定範本；不要複製其 Godot 標識、問號磚、道具槽、選單面板、角色造型或具體文案。
